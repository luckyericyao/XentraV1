# Xentra 首页审计与执行目标

审计日期：2026-08-10  
范围：`/`、`/zh` 的桌面与移动端首屏、滚动结构、公开业务入口、合作转化与基础质量。

## 已经成立的部分

- 深色、暖象牙色与低饱和 brass 的主色方向已经具备高级感。
- Newsreader 与 Instrument Sans 的搭配建立了清晰的编辑型层级。
- 三家业务均有独立章节、官网入口和公开页面证据，母公司不需要靠空泛描述建立可信度。
- 导航、语言切换、跳过链接、移动菜单、预填邮件和复制邮箱已经形成完整的基础交互。
- 页面没有明显横向溢出，英文与中文都能在桌面和手机上保持可读。

## 主要不足

### 1. 母公司角色需要更早、更硬地出现

首屏原本主要讲市场判断，用户要滚动到业务布局或集团架构才会确认 Xentra 是母公司。对 operating group 来说，第一屏应该同时交代集团角色、业务规模和共用方法。

### 2. 长页面中存在“同一信息的三次出现”

业务卡片、集团架构和业务章节都在介绍三家公司。完整证据章节值得保留，但前两处必须更像索引和架构图，不能继续承担完整说明，否则页面容易像项目档案，而不是有节奏的集团叙事。

### 3. 一些模块仍然带有模板化卡片感

理念、新业务方向和运营方法都使用相似的圆角卡片。它们表达的是判断标准与工作原则，更适合使用规则线、编号和编辑型列表，让真正的业务卡片成为页面唯一的主要卡片系统。

### 4. 交互表面略偏 SaaS

大量胶囊按钮、圆形菜单和阴影会把整体拉回普通产品官网。集团级页面更适合窄边框、短半径、轻微位移和更克制的悬停反馈。

### 5. 可信度必须依靠可核验事实，而不是继续加文案

业务官网、业务路径和公开证据是优势。自定义域名、公司实体、团队名单、邮箱收发状态和经营数据仍需外部权限或事实确认，不能在页面里用未经核验的内容填充。

## 专家与高审美复盘

从高端母公司官网、编辑型商业网站和客户首次访问路径的角度看，当前版本已经脱离普通 SaaS 模板，但仍有四个需要持续盯住的判断：

- **首屏信号要服务于母公司角色。** 装饰不能像产品演示。它应该让人感到这是一个在组织方法、业务和责任边界的集团。首屏登记栏与架构线因此比更多动效更有价值。
- **业务证据要成为可信度来源。** 真实业务入口、公开路径和带日期的截图比新增口号更能帮助客户判断“这家公司是否真的在运行”。所有证据都必须可访问、可追溯、不过度承诺。
- **首页要有节奏，而不是把所有信息都塞进一页。** 概览负责快速定位，架构负责解释母公司关系，分章负责证据。若继续变长，应拆出业务索引页，而不是再次压缩到不可读。
- **品牌信任还受外部表面影响。** Vercel 项目域名、未核验的企业邮箱配置、缺少已确认的实体与团队信息，都会限制“高端集团”的可信上限。这些不是 CSS 问题，必须由域名、部署和企业资料权限解决。

## 优先目标

1. **母公司清晰度**：在首屏 5 秒内看懂 Xentra 是母公司、拥有 3 家业务公司，并提供 4 个共用运营动作。
2. **视觉权威感**：保持近黑、暖象牙、低饱和 brass 的系统；删除会让人联想到 AI 数据流、模板胶囊或 SaaS 仪表盘的装饰。
3. **证据型转化**：每家公司都能从概览进入真实官网、公开业务路径和业务分章；联系入口只承诺已知事实，不制造表单或经营数据。
4. **滚动效率**：首屏、理念、业务、架构、证据、方法、合作各自承担一个任务；继续增长时优先拆页，不让首页成为资料库。
5. **生产可信度**：每轮都通过 lint、build、smoke、双语桌面/移动检查，并核对公开部署与外链可达性。

## 执行目标

1. **集团先行**：首屏明确母公司、03 家业务公司和 04 个共用运营动作。
2. **编辑型节奏**：把非业务内容从重复卡片改为规则列表，减少视觉噪音和滚动疲劳。
3. **业务可进入**：公司卡片只负责快速理解与进入，完整章节负责证据、判断和交付说明。
4. **安静的转化**：保留真实官网入口与预填邮件，不增加虚假表单、虚构指标或未经确认的背书。
5. **生产质量门槛**：每轮改动都通过 lint、build、smoke、英文/中文、桌面/移动和公开部署检查。

## 本轮落地

- 首屏增加集团登记栏：`01` 母公司方法、`03` 垂直业务公司、`04` 共用运营动作。
- 英文首屏改为 `Parent operating group`，业务区改为 `Operating Companies`，并补充一句短的判断主张。
- 理念与新业务方向改为编号规则列表。
- 运营方法改为无卡片的横向规则行。
- CTA、语言切换、移动菜单、复制邮箱和返回顶部统一为更克制的短半径边框。
- 业务卡片增加轻微悬停上移，保持业务入口和证据章节之间的层级关系。
- 隐私页与 404 页同步主站的短半径交互表面，避免信任页面保留旧的 SaaS 胶囊按钮。
- 隐私联系入口增加明确邮件主题，并纳入 smoke 回归检查。
- 修正跳过链接点击后的焦点时序，确保焦点最终落在主要内容节点，而不是停留在 `body`。
- 压缩业务概览卡，只保留主张与两个入口；详细叙事和公开证据集中在滚动分章中。
- 首屏架构背景改为静态分支线与方形节点，降低通用 AI 数据流的既视感。
- OG 分享图移除胶囊标签，改为与站内一致的线性 eyebrow，保持品牌在站外分享场景的完整性。
- 跳过链接保留原生锚点，并补充 Enter/Space 的显式聚焦路径；线上键盘复验可落到 `main#top`。
- 收紧非证据区的垂直节奏，将“我们建立什么”改成紧凑登记带；业务证据、三条滚动分章和合作路径保持完整。英文/中文本地渲染高度分别减少约 639px / 474px。
- 将“新业务方向”并入联系区，保留 `#directions` 深链接和五项筛选标准，让合作方先判断方向匹配，再选择运营者、专家或资本路径。
- 强化 JSON-LD 的集团关系：三家业务使用稳定的组织 ID，首页声明母公司为主实体，并写入本轮真实核验日期；smoke 同步检查这些字段。
- 在业务概览标题旁显示 `Public product evidence / Checked ...`，让真实业务证据在第一次出现三家公司时就可见。
- 中文业务标签改为更像母公司 portfolio register 的原生表达：`企业 AI 能力`、`本地信任网络`、`生命科学供应`，并统一 `AI Agent Coach` 品牌名；首屏标签与 OG 分享图同步这套命名。
- 移动端集团架构补充竖向母公司脊柱与三条业务连接线，保留三家公司在窄屏上的母子关系；桌面端继续使用横向三列架构图。
- 中文首屏副标题在极窄屏启用 `keep-all` 换行，避免“运营”等词被拆开，保持 320px 设备上的品牌排版完整性。
- 三张业务组合卡加入轻量的 `Public product evidence / Checked ...` 登记行，让证据状态在首次看到业务时就与真实入口同时出现。
- 英文桌面首屏将三条 portfolio 标签移入集团登记栏右侧，确保 1280×720 首屏直接呈现母公司旗下方向；平板与手机继续采用纵向排列。
- 中文三条业务简介改为更自然的业务档案语气，并为 AI Agent Coach、Localhost、BioAxis 的关键描述加入 smoke 回归标记，避免后续直译或空泛文案回退。
- 集团架构三条内部入口补充双语可访问名称，明确它们会进入对应业务分章；smoke 同步检查 6 个 locale-specific link labels。

## 下一轮建议

- 在有真实团队、实体和经营数据后，加入一小块事实型集团信息，而不是再增加口号。
- 确认品牌域名和企业邮箱后，替换现有 Vercel 入口并重新验证 TLS、重定向、canonical、邮件收发和垃圾邮件策略。
- 若页面仍显得过长，优先把完整证据章节拆成独立的业务索引页，而不是删掉公开证据。
